## 2. 验证目标

用户提出的目标是：

> 找一个公开策略和结果，在本地跑同样策略。如果收益能对上，就可以同时验证数据、策略模块和回测模块。

这个目标可以拆成三层：

1. 数据是否可信：本地行情字段是否正确、口径是否稳定。
2. 策略是否可信：策略信号是否按规则正确产生。
3. 回测是否可信：信号、持仓、收益、换手、成本是否按预期计算。

为了避免把问题混在一起，本轮采用了分层验证方法。

这里需要特别说明：“数据完全正确”不能只靠本地字段自洽证明。它至少需要两类证据：

1. 本地数据内部一致：例如 OHLC、成交量单位、涨跌幅、复权序列没有明显错误。
2. 本地数据外部一致：与一个或多个可信外部数据源在指定日期、指定复权口径下逐项对齐。

目前第 1 类证据已经完成，第 2 类证据只有程序框架，还没有稳定跑出结果。

## 6. 公开策略复现一：510300 60 日均线

来源：

- 投资者教育 PDF：`https://www.investor.org.cn/xxzx/tjzl/tjnrgmjytx/bk/kj/jyxl_3783/202311/P020231116582854616218.pdf`

公开规则与结果：

- 标的：沪深300ETF `510300`
- 区间：2018/12/31 - 2021/06/30
- 规则：收盘价上穿 60 日均线买入，跌破 60 日均线卖出空仓。
- 公开买入持有收益：79.85%
- 公开 60 日均线择时收益：156.76%

这个案例的优点是公开材料给出了明确收益数字，适合作为“公开收益对齐”候选。缺点是材料没有给出完整代码、复权口径、成交价、费用、调仓明细，也没有给出可下载净值曲线。

本地复现脚本：

```bash
python3 research/replication/replicate_510300_ma60_public.py
```

本地结果：

| case | return | target_return | diff_vs_target |
| --- | ---: | ---: | ---: |
| local_buy_hold | 74.21% | 79.85% | -5.64% |
| local_ma60_next_close | 0.81% | 156.76% | -155.95% |
| local_ma60_same_close_lookahead | 106.74% | 156.76% | -50.02% |

结论：

- 这个公开案例没有对齐。
- 首先买入持有收益就有 5.64 个百分点差异，说明数据口径、复权方式、统计起止点或标的口径可能不同。
- 策略收益差异更大，说明交易时点、上穿/下穿定义、是否允许当天成交、是否使用指数而非 ETF、是否使用未复权价格等细节均可能不同。
- 该案例目前只能作为“待解释差异样本”，不能作为系统已通过公开收益对齐的证明。

对原始目标的贡献：

- 可以检验“公开收益对齐”这条链路。
- 当前结果是失败样本，反而说明还不能宣布数据、策略、回测三者整体完全正确。

## 7. 公开策略复现二：JoinQuant 核心 ETF 轮动

来源：

- JoinQuant 公开帖子：`https://www.joinquant.com/community/post/detailMobile?postId=50158`

公开规则：

- 每天开盘前运行。
- ETF 池：
  - `518880.XSHG` 黄金 ETF
  - `513100.XSHG` 纳指 100
  - `159915.XSHE` 创业板 100
  - `510300.XSHG` 沪深 300
- 截至目标日前一日，取最近 25 个交易日收盘价。
- 对 `log(close)` 做线性回归。
- 计算：

```text
score = annualized_return * r_squared
```

- 每天选择 score 最高的 1 只 ETF。

公开结果：

- 帖子给了规则和可运行代码。
- 评论中提到该策略回测大约在 15~18 倍收益之间，也有用户反馈约 15~16 倍。
- 但帖子没有完整公开收益表、精确回测区间、手续费、成交价、净值曲线和每日调仓记录。

本地复现脚本：

```bash
python3 research/replication/replicate_etf_regression_momentum.py
```

本地实现假设：

- 数据：本地前复权日线。
- 区间：2018-02-05 至 2025-12-30。
- 信号：每日用目标交易日前可见的 25 日收盘价计算 `reg_momentum_25` 排名。
- 交易：日频回测，使用下一交易日收益。
- 成本：本次验证设为 0，目的是检验信号和回测计算一致性。

本地结果：

| 指标 | 结果 |
| --- | ---: |
| 累计收益 | 576.77% |
| 年化收益 | 28.58% |
| 年化波动 | 25.55% |
| Sharpe | 1.12 |
| 最大回撤 | -29.99% |
| 胜率 | 49.66% |

校验方法：

- 系统策略 `ETFRegressionMomentumStrategy` 跑回测。
- 同时用独立向量化计算：

```text
每个交易日：
  对 4 只 ETF 按 reg_momentum_25 排序
  选择 score > 0 且最高的 ETF
  expected_return = 该 ETF 的 fwd_ret_1
```

校验结果：

- `engine_cum_return = expected_cum_return`
- `cum_return_diff = 0`
- `max_daily_return_diff = 0`
- 状态：pass

结论：

- 这个案例完成了“公开规则复现 + 系统策略/回测与独立实现一致”的验证。
- 但因为公开帖子没有精确收益表，所以还不能说“公开收益也完全对齐”。

对原始目标的贡献：

- 可以证明我们实现的 ETF 回归动量策略逻辑和回测执行逻辑是一致的。
- 不能单独证明公开平台收益能被本系统精确复现。
- 也不能证明本地数据与 JoinQuant 数据完全一致，因为没有可逐日对齐的公开净值或交易记录。

## 8. 是否偏离最初目标

有一部分偏离，也有一部分是必要的分层验证。

没有偏离的部分：

- 我们确实找了公开策略。
- 我们确实把公开规则实现到系统里。
- 我们确实验证了策略模块和回测模块能与独立实现完全一致。

没有完全达到的部分：

- 还没有找到一个“公开策略 + 完整公开收益结果 + 明确所有交易假设”的样本，并让本系统收益完全对齐。
- `510300 MA60` 有公开收益数字，但没对齐。
- `JoinQuant ETF 轮动` 有清晰代码规则，但缺少严格公开结果表。

所以严格说，当前任务不是“完全完成”，而是完成了系统校准的前两层，并建立了继续做公开收益对齐的框架。

我对自己前面工作的审视：

- 没有偏离的是：先修数据、建质量门、修回测空仓 bug、做独立公式校验，这些都是达到最终目标前必须排除的基础问题。
- 有偏离风险的是：ETF 轮动案例容易被误解成“公开结果已对齐”，但它实际只完成了“公开规则复现”和“内部一致性验证”。
- 需要纠正的表述是：当前不能说“已经通过公开策略收益验证了整个系统”，只能说“已经具备继续做公开收益精确复现的基础”。

## 9. 当前系统可信度判断

可以较有信心地认为：

- 已下载日线数据的字段一致性没有明显问题。
- 回测引擎的基础收益计算是正确的。
- 策略接口对简单和中等复杂度策略的信号执行是正确的。
- 当前发现过的关键回测 bug 已修复。

仍不能完全确认：

- 不同数据源之间是否长期完全一致。
- 历史股票池是否无幸存者偏差。
- 公开策略收益是否能在明确口径下完全复现。
- 带交易成本、滑点、开盘价/收盘价成交假设时是否与第三方平台完全一致。

## 10. 下一步建议

优先继续找一个更严格的公开复现样本：

- 有完整代码。
- 有明确回测区间。
- 有明确交易价格。
- 有明确手续费和滑点。
- 有公开净值曲线或逐年收益表。
- 最好有调仓记录。

推荐方向：

- JoinQuant / BigQuant / MyQuant 上带完整回测结果的 ETF 轮动代码。
- 只做 ETF，不先做全市场股票，避免历史股票池和停牌问题干扰。
- 先要求“不含费用的毛收益”对齐，再逐步加入费用、滑点、成交价假设。

下一轮严格验收标准建议如下：

| 阶段 | 通过条件 |
| --- | --- |
| 数据 | 同一标的、同一复权口径、同一日期的 OHLCV 与外部源抽样误差为 0 或在明确定义的精度范围内 |
| 策略 | 每个交易日的候选池、分数、目标持仓与公开代码或独立实现一致 |
| 回测 | 每日收益、累计净值、换手、费用与公开结果逐日或逐月对齐 |
| 结论 | 三层全部通过后，才把该公开样本标记为 replication pass |
